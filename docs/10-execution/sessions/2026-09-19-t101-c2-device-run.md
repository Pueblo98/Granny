# T-101 C2 bounded tablet evidence session

## Scope and authority

Simon authorized a bounded C2 device run on `TBL-01`: enable Developer
options and USB debugging, trust this computer, run `adb devices`, install
only the two reviewed debug APKs, manually grant or deny per-session
MediaProjection consent for synthetic fixture cases C2-01–C2-12, record only
content-free results, uninstall both APKs and restore debugging settings.

This authority excludes personal apps, accounts or data; screenshots; raw
captured content; transport identifiers in repository evidence; unrestricted
shell commands; runtime network egress; other packages; accessibility-service
enablement; store/provider contact; T-104; and promotion of T-101 or
GATE-03/04/06. No `adb shell` command is authorized. Cases without a safe,
synthetic route inside these bounds will be recorded as unrun rather than
broadening the procedure.

## Reviewed artifacts and planned procedure

The authorized source is task commit
`aac537f1f350292e637b49fd8c05aefad1ea4abe`. Before installation, the
session will recheck these reviewed APK digests:

- fixture: `b4c4a6bd5ba090067ab1c92dc70f329336f5042301796ed01d8f762ebc93fd1d`
- observer: `5688e33734b1717baf555ec6c5d450cf5bcb05ac19484b4e3ece08ca61dcb9c1`

Device discovery is limited to `adb devices` with output reduced locally to
transport-state counts so the tablet identifier is neither displayed nor
recorded. Installation is limited to the reviewed fixture and observer APKs.
The apps are operated manually against synthetic fixture scenes; no screenshot,
screen recording, log capture, package inventory or personal-app inspection is
part of the run. Teardown is limited to uninstalling
`org.pueblo98.granny.c2observer` and `org.pueblo98.granny.c2fixture`, followed
by manual USB-debugging restoration on the tablet.

## Evidence state

Device evidence was unrun at session start. Host compilation, static inspection,
signing verification, lint and 14 pure tests remain prior host evidence, not
device evidence. The API 36 selected-package identity oracle remains unresolved
and cannot be waived by a successful synthetic observation.

## Live device checkpoint

Exactly one authorized transport was present; only the count was displayed.
Both reviewed APK digests matched and both APK installs returned `Success`.

- C2-01: the human cancelled Android's app-sharing chooser. The observer
  reported that capture did not start. This is content-free evidence for the
  denial path.
- Unplanned route deviation: on a second attempt the human selected Android
  Settings rather than the synthetic fixture. The observer returned
  `UNAVAILABLE` because the content did not match the approved fixture; after
  the human pressed Stop it reported `STOPPED` and no explanation. No content,
  screenshot or app details were requested or recorded. This attempt is not
  counted as a completed synthetic C2 case and no nonfixture selection will be
  repeated.
- C2-02: the human opened the default normal scene, returned to the observer,
  selected only the synthetic fixture app window in Android's chooser and
  reported `EXPLAINED`. This is provisional evidence for one bounded
  in-memory classification and automatic release. It is not independent proof
  of the selected package identity.
- C2-03: the human selected the synthetic fixture's untrusted-instruction
  scene and reported `EXPLAINED`; no other app opened and no app action
  occurred. This is provisional content-free evidence that fixture text was
  treated as data rather than authority.
- C2-04: the human selected the synthetic stale scene and reported
  `EXPLAINED`, then confirmed that the result carried the required instruction
  to recheck the current screen before relying on it.
- C2-05: the human selected the synthetic private-canary scene and reported
  `WITHHELD`. No canary content is recorded here.
- C2-06 first attempt: after the human selected the synthetic secure scene,
  the observer unexpectedly returned `EXPLAINED` with the normal-scene
  classification rather than protected/unavailable. This is a candidate
  fail-closed violation; one controlled synthetic-only repeat is pending to
  distinguish a route-selection error from reproducible behavior.
- C2-06 controlled repeat: after Stop, the human reopened the fixture,
  selected and visually confirmed the protected scene, waited, returned to
  the observer and selected only the fixture app window. The observer again
  returned `EXPLAINED` with the normal-scene classification. C2-06 therefore
  **fails** on this configuration: protected content does not reliably fail
  closed and appears to admit a stale/prior synthetic frame classification.
- C2-07: the human used the dedicated delayed-invalidation control, left the
  Android chooser open beyond the three-second invalidation point and then
  cancelled. The late result was reported as ignored. The human did not see a
  system sharing indicator during this cancelled case. On reviewing a
  completed stale-fixture run, the human did observe Android's sharing
  indicator for roughly three seconds before automatic release. Timing is a
  human estimate and no recording was retained.
- C2-08: while attempting the manual Stop race, the human believed whole-screen
  sharing was needed and the tablet became temporarily unresponsive, including
  its hardware controls. The tablet recovered after the USB connection was
  unplugged and reconnected; no reset was performed. The case is **aborted**,
  not passed. All remaining capture attempts were stopped. C2-10 and C2-12
  remain unrun. No screen contents or personal-app details are recorded.
- C2-09: the human made one attempt to activate Android's visible sharing
  indicator and stop the session before automatic release. Repeated taps did
  not expose or activate a Stop control before the short session ended. The
  system-revocation path is therefore **inconclusive/unrun**, not passed; the
  current timing does not provide a reliable manual oracle on `TBL-01`.

## Teardown and disposition

After the safety stop, the redacted transport check showed the reconnected
tablet required fresh trust. The human re-enabled USB debugging only long
enough to approve teardown. Both exact-package uninstall commands returned
`Success`. The human then revoked USB-debugging authorization, disabled USB
debugging and Developer options, and unplugged the cable.

The [content-free evidence ledger](../../08-research/2026-09-19-t101-c2-device-evidence.md)
owns the final case dispositions. C2 is not admitted: C2-06 failed twice,
C2-08 was aborted after a temporary tablet-unresponsiveness event, C2-09 is
inconclusive, C2-10/C2-12 are unrun, and package identity remains unresolved.
T-101 and GATE-03/04/06 remain open.
