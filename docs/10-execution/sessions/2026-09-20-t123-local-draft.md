# T-123 native fictional local draft flow

## Scope and authority

Simon requested the local draft flow after Setup/Capability Center and while
media-route evidence is investigated. This bounded source task adds one finite,
fictional request to the existing native conversation coordinator: clarify
between two same-name fictional recipients, show the exact local recipient,
channel and body, then keep the draft only in the current process.

No external app, intent, contact, account, provider, messaging SDK, network,
send, delivery claim, persistent draft store or device action is authorized.
Candidate builds fail closed; the fixture is available only in the existing
debug/synthetic-lab mode.

## What changed

- Extended the existing main-thread conversation coordinator with three local
  draft surfaces: same-name recipient clarification, exact draft preview and a
  process-only ready state. No parallel UI authority or adapter was introduced.
- The finite interpreter recognizes only the exact fictional request (accepting
  straight or curly apostrophe), preserves the exact body and offers only
  `person-a` / `David — brother` and `person-b` / `David — neighbour` on
  `Fixture messages`.
- Recipient choice increments the conversation generation, shows endpoint,
  channel and body under `Fictional local draft — not sent`, and never creates
  a permit. `Keep this draft here` changes only coordinator memory.
- Editing, Stop, background, recreation, place change and Done clear the local
  binding. Release/candidate mode denies the fixture. The renderer supplies
  accessible written choice buttons and uses the existing Type/Talk, focus,
  text-scale and explicit readback controls.
- Bumped the review artifact to version code 4 / `0.4-local-draft`. No new
  permission, dependency, component, store or network path was added.
