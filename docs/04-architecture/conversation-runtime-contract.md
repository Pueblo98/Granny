# Conversation runtime contract

Version **granny.conversation.v1**. Backend edits this boundary; frontend reviews and consumes it. This implements Simon's 2026-09-15 local browser/backend/MCP experiment only. Product execution invariants remain owned by [execution protocol](../03-agent/execution-protocol.md); this is its bounded demo transport, not an Android adapter or T-103 completion. Technical agreement is not product acceptance.

## Ownership and modes

Backend is the sole owner of sessions, turns, prepared actions, confirmation validity, execution state, cancellation and verified results. Frontend owns layout, copy, keyboard/focus and presentation state. Connected events never run the scripted model/scheduler. Scripted mode remains a separate local UI experience. `demo` means stub model + real MCP + real isolated demo store, no egress. `live` means opt-in Qwen/OpenRouter interpretation + the same local authority/MCP/store, synthetic text only. Neither mode sends a message or operates Android.

## HTTP and identifiers

Same-origin loopback server; exact Host/Origin enforcement, no CORS or public bind. JSON only, no streaming. Commands acknowledge immediately; frontend polls events while pending (suggested 250 ms, at most one poll in flight). Client IDs are UUIDs generated by crypto.randomUUID. Backend sessionId/turnId/actionId/eventId and confirmationToken are opaque UUIDs. `requestId` identifies one command; identical retry returns current snapshot without execution; reuse with changed content is HTTP 409 `request_conflict`.

GET `/api/runtime/config` → `{version, available:true, liveAvailable:boolean, model, limits}`. No key or environment exposure.

POST `/api/runtime/session`:

```json
{"version":"granny.conversation.v1","requestId":"UUID","mode":"demo","consent":true}
```

Returns HTTP 201 Snapshot. `consent:true` attests the UI's explicit fictional-data disclosure; live also requires the server's `--live` opt-in and private server-side key. Session creation is idempotent by requestId. No model call on create. Maximum 8 sessions/process; 64 commands/session; one active operation/session; 512 events/session; 30-minute absolute session lifetime. No session resume after process restart. No storage in browser localStorage; retain session/cursor in tab memory only.

POST `/api/runtime/command`: common fields `{version,sessionId,requestId,kind,payload}`; all keys required, unknown keys rejected. Payload variants:

| kind | Exact payload | Effect |
|---|---|---|
| turn | `{text:string}` (1–2000 UTF-16 units, nonblank) | New turn; invalidates older preview/work before model interpretation |
| clarify | `{turnId,choiceId:string}` | Select one offered fictional person or channel; choice must belong to current clarification |
| revise | `{actionId,recipientId,channelId,body}` | Replace exact current preview; IDs must be approved fictional IDs, body 1–2000; new action/token required |
| confirm | `{actionId,confirmationToken}` | Explicit preview-button action only; single admission of exact immutable prepared action |
| cancel | `{}` | Stop latch, epoch advance, invalidate all pending work/approval; no provider round |

Returns HTTP 202 Snapshot after synchronous admission/denial validation, before asynchronous work. `turn` while an admitted draft effect is unresolved is HTTP 409 `effect_unknown`; no duplicate execution through a new request. User typed “yes” is an ordinary turn, never confirmation. A newer turn can replace model/lookup/preparation; it cannot hide an already-dispatched uncertain effect.

GET `/api/runtime/events?sessionId=UUID&after=0` → Snapshot; `after` is last contiguous applied seq, nonnegative and no greater than server cursor. Poll only this route; no raw MCP endpoint available to browser.

Snapshot shape: `{version,sessionId,mode,epoch,cursor,state,events:Event[]}`. `cursor` is highest emitted sequence, `state` the authoritative current state; events are all seq > after (commands/session responses use after=0). No dropped events within session bounds. HTTP errors: `{version,error:{code}}`, never raw provider/tool messages. 400 schema, 403 origin/consent, 404 session unavailable, 409 stale/conflict, 429 budget, 503 unavailable. Handle errors without inventing an execution result.

## Events and authoritative states

Every Event has `{version,sessionId,turnId,requestId,actionId,eventId,seq,epoch,type,state,data}`. turnId/actionId may be null; requestId is the causal command; seq starts at 1 and strictly increases per session. epoch advances on a new turn, revision and Stop. Terminal state changes fence late worker results. No model output can emit events directly.

| type | state | data |
|---|---|---|
| progress | interpreting / resolving / creating / verifying | `{phase}` matching state |
| chat | idle | `{text,source:"stub-model" or "live-model",verified:false}`; plain untrusted model prose, no action claim |
| clarification | clarifying | `{field:"recipient" or "channel" or "body",prompt,choices:[{id,label,detail}]}`; body has empty choices, answer with a new turn |
| preview | preview | `{actionId,recipient:{id,label,detail},channel:{id,label},body,effect:"create_demo_draft",effectLabel:"Create an unsent draft in the local demo",confirmationToken,expiresAt,provenance:{turnId,source:"user-span" or "user-edit",start,end}}` |
| result | completed | `{draftId,recipientId,channelId,body,effect:"demo_draft_created",verified:true,sent:false,message:"Draft created in the demo. Not sent."}` |
| error | failed / unknown | `{code,effect:"none" or "unknown",retryable:false}` |
| cancellation | stopped / unknown | `{effect:"none" or "unknown"}` |

Initial state idle, epoch 0, no events. Preview expires after 60 seconds using monotonic backend time; expiresAt is ISO display information only. Expiry rejects confirmation as `confirmation_stale`; UI keeps the preview readable and can request revision to obtain a fresh preview. End offsets are exclusive UTF-16 indices into the original turn; user-span body is sliced from original input, never generated/repaired/normalized. Missing or invalid span requires clarification. user-edit provenance uses start 0/end body.length. Person/channel model slots must also exactly occur in the original input; otherwise clarify, never guess. Identity lookup is bounded through MCP, not model-selected endpoints.

## Ordering, confirmation, disconnect and Stop

Apply only matching version/session events. Deduplicate by seq/eventId, apply strictly contiguous seq, fetch from last contiguous cursor on gaps. Ignore stale-epoch presentation events after newer epoch observed. A replay must not resurrect a confirm control. Snapshot state/epoch overrides old presentation; historic events may remain readable, but only its current preview can be actionable. Disable confirmation synchronously on click, edit, Stop, mode change, or transport failure. Never automatically resend a confirmation with a fresh requestId.

Confirmation binds server-side immutable exact recipient ID, channel ID, body, effect, actionId, session, turn, epoch, policy version and expiry. The token is issued for preview and becomes authority only through the separate explicit confirm command; model never receives it. Any change mints a new action/token. Consumed/stale/missing/wrong/replayed tokens reject; duplicate identical command only retrieves its existing snapshot. Browser input is not authenticated human identity against malicious local software; this development service assumes a trusted same-origin UI and local machine.

Transport loss does not prove cancellation. UI disables actions, shows connection uncertainty and attempts read-only event recovery for the existing session/cursor. Send cancel when reachable; await cancellation event before claiming stopped. Server continues an already-admitted bounded operation, retains events and never retries a write. Reload/process restart starts a new UI session; no pending confirmation is restored. A new runtime owns a new empty temporary demo store; old uncertainty cannot be treated as evidence of no earlier effect.

Stop invalidates queued work synchronously, aborts provider/MCP request waits, rejects late results and emits stopped if no effect entered dispatch. Once a write entered MCP, Stop reports unknown, forbids further automatic reads and quarantines the session against additional drafts. An unknown effect is terminal for that session; no Retry action. Closing/mode changes issue cancel first, preserving uncertainty if unreachable.

## Capability and resource boundary

Fixed in-repository server only. Official MCP client/server SDK **2.0.0**, Zod **4.6.5** and lockfile pin dependencies; MCP protocol 2025-11-25 is observed in initialization and required by an interoperability test. stdio child receives no OpenRouter key and accepts no arbitrary server path, network target or filesystem path from model/browser. Tools: `demo_contacts_resolve`, `demo_draft_create`, `demo_draft_read`. Strict input/output validation and a second independently read stored record precede completed. Tool descriptions/results are untrusted; no returned text is treated as instructions or provider context. Malformed/out-of-scope output fails closed.

Per turn at most 8 MCP operations, each at most 5 seconds; model at most 25 seconds; no automatic retries. Shared live process limits remain Qwen's 20 calls/process, 6/minute, one in flight, 768 output tokens, 12 messages/12000 characters maximum context, $0.15/M input and $0.47/M output routing ceilings, data_collection deny, required parameters, no fallback. These are rate/token/route caps, not account-wide billing enforcement. No cap increase or paid CI calls.

Store contains only synthetic drafts in an isolated process-lifetime temporary directory, removed on graceful shutdown. Crashes can leave temporary synthetic files; no automatic action replay. No transcript/credential/raw MCP/provider-body logging. Diagnostics allow codes, counts, durations, versions and opaque IDs only. No production encryption/deletion guarantee or personal-data authority.
