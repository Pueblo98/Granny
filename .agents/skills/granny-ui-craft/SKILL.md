# Granny interface craft

Read [AGENTS](../../../AGENTS.md), the [conversation-first plan](../../../docs/02-design/conversation-first-plan.md), the existing [design handoff skill](../granny-design-handoff/SKILL.md), and the selected J/SCR/CMP owners. Canonical product, safety, accessibility, voice and token contracts win over this craft layer. A visual idea never grants implementation, device, Figma, dependency, brand or acceptance authority.

Identify the requested mode:

- **Shape:** define the surface's user job, content, hierarchy, states and interaction thesis before code.
- **Explore:** produce three meaningfully different structural directions against identical behavior, copy and fixtures. Read [direction and variation](references/direction-and-variation.md).
- **Distill:** remove controls, containers or steps that do not earn their place while preserving discoverability, touch access, confirmation and Stop.
- **Critique:** assess an existing source and rendered view for product specificity, hierarchy, dignity, accessibility, state coverage and platform fit. Read [critique and hardening](references/critique-and-hardening.md).
- **Harden:** cover realistic long content, maximum scale, focus/keyboard, permissions, loading, failure, expiry, interruption, partial and unknown outcomes.

For shape or explore work, state one compact design read: audience/context, present goal, emotional posture, active medium and eventual platform. Base directions on the actual conversation-led job; do not select aesthetic labels randomly. Treat the rejected feature-tile Home as an anti-reference, not an implementation to polish.

Keep novelty in composition, content treatment, rhythm and a small number of memorable details. Keep risky actions conventional and explicit. Avoid interchangeable AI defaults: capability dashboards, repeated floating cards, pills for ordinary labels, decorative gradients, gratuitous glass, generic assistant sparkles, fake metrics, hidden icon-only controls and motion used to disguise weak hierarchy.

For browser work, inspect source and a rendered reference when available, then run the repository's model/browser checks after an authorized edit. For native work, use the applicable official `adaptive`, `edge-to-edge` or `testing-setup` skill only after a native Compose task is authorized and its prerequisites are actually present. A browser screenshot is not Android, TalkBack, device or human evidence.

Hand off the chosen direction or critique with: target; user job; structural thesis; what is deliberately absent; required states; voice/touch/focus behavior; token maturity; Android translation risks; checks performed; and remaining decisions/evidence. Do not generate a second product brief, design-system store or token authority.
